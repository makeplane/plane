# Phase 4 — UI Design Contract

> Visual and interaction contract for the Workspace Template Management UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Brownfield note:** Plane already ships a mature, token-driven design system (`packages/tailwind-config/variables.css`, `@plane/ui`, `@plane/propel`). This phase invents **no** new visual language. Every value below is drawn from that existing system. The contract's job is to lock which existing tokens and component idioms this feature reuses so the executor implements consistently with webhooks / labels / project-states settings screens.

## Spacing Scale

Plane's spacing follows Tailwind's default 4px base scale; page gutters use the `--padding-page` token (1.35rem ≈ 22px). Declared values used by this phase (multiples of 4):

| Token | Value | Usage                                                                                                     |
| ----- | ----- | --------------------------------------------------------------------------------------------------------- |
| xs    | 4px   | Icon-to-label gaps, drag-handle inset, inline chip padding                                                |
| sm    | 8px   | Compact spacing inside rows, button icon gaps, form field label-to-input                                  |
| md    | 16px  | Default gap between form fields, list rows, header control spacing                                        |
| lg    | 24px  | Section padding, gap between the two provenance sections, editor section blocks                           |
| xl    | 32px  | Layout gap between page heading and content (existing settings use `mt-4`/`mt-6`)                         |
| 2xl   | 48px  | Major vertical break between the last editor section and the sticky action bar region                     |
| 3xl   | 64px  | Empty-state vertical breathing room (existing `rootClassName="py-20"` ≈ 80px is the sanctioned exception) |

Exceptions:

- Page container width is capped by `SettingsContentWrapper` at `max-w-225` (900px) centered; editor may use `hugging` mode (`px-page-x lg:px-12`, full width) because the 5 structured sections need horizontal room per D-09.
- Empty-state padding uses the existing `py-20` (80px) convention rather than a 4-multiple of the scale above — matches labels/webhooks empty states.
- Row min-height follows existing settings rows (~42px, per labels `Loader.Item height="42px"`); touch targets on the overflow (⋮) and drag handle are 20px icon boxes inside a ≥32px hit area.

## Typography

This feature uses a 4-size / 2-weight subset of Plane's type scale. All roles map to existing `text-*` utility tokens — do not hand-roll `font-size`/`line-height`.

| Role                                                                             | Size | Weight        | Line Height | Token                                                                                             |
| -------------------------------------------------------------------------------- | ---- | ------------- | ----------- | ------------------------------------------------------------------------------------------------- |
| Page heading (SettingsHeading title)                                             | 20px | 500 (medium)  | 1.2         | `text-h4-medium` (pass `variant="h4"` to `SettingsHeading`)                                       |
| Section heading ("System templates" / "Custom templates", editor section titles) | 16px | 500 (medium)  | 1.2         | `text-h6-medium`                                                                                  |
| Body / row label / form input text                                               | 14px | 400 (regular) | 1.4         | `text-body-sm-regular` (labels/values), `text-body-sm-medium` for the row's primary template name |
| Label / description / metadata caption                                           | 13px | 400 (regular) | 1.4         | `text-body-xs-regular` (section descriptions, counts, helper text)                                |

Weights: exactly two in active use — **regular (400)** for body, descriptions, and inputs; **medium (500)** for headings, the primary template name in a row, buttons, and active tabs/toggles. (`semibold`/`bold` exist in the system but are **not** introduced by this feature.)

Line heights: headings 1.2 (Plane heading tokens), body/caption 1.4 (Plane body tokens). Do not override.

## Color

Plane is a dual-theme (light/dark + high-contrast) system built on semantic OKLCH tokens. The 60/30/10 split maps to Plane's surface/layer/accent token families. Executor MUST use the semantic Tailwind classes (e.g. `bg-surface-1`, `text-primary`, `border-subtle`), never raw hex or raw palette steps.

| Role            | Value (semantic token)                                                               | Usage                                                                                            |
| --------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Dominant (60%)  | `--bg-surface-1` (`bg-surface-1`) — light `oklch(1 0 0)` / dark `neutral-100`        | Page background, editor canvas, primary reading surface                                          |
| Secondary (30%) | `--bg-layer-1` (`bg-layer-1`) + `--border-subtle` (`border-subtle`)                  | Template rows, section cards, form field wells, inline add/edit row containers, section dividers |
| Accent (10%)    | `--bg-accent-primary` (`bg-accent-primary`, brand-default) + `--text-accent-primary` | Reserved list below only                                                                         |
| Destructive     | `--bg-danger-primary` / `--text-danger-primary` / `--border-danger-strong`           | Deactivate action + its confirmation modal only                                                  |

Accent reserved for (explicit — never "all interactive elements"):

- The primary CTA button ("New template", editor "Save template") — `Button variant="primary"`.
- The active/selected state of the "Show deactivated" toggle when engaged.
- The "Default" state marker highlight in the states section (matches project-states default badge).
- Focus ring on inputs/controls (`ring-accent-strong`).

Everything else uses neutral tokens: row hover = `bg-layer-1-hover` / `hover:bg-layer-1`; secondary buttons = `Button variant="neutral"` / `outline-neutral`; text = `text-primary` / `text-secondary` / `text-tertiary`; icons = `text-tertiary` default. Duplicate/Edit primary row actions are neutral (icon or `neutral` button), NOT accent — accent stays scarce.

Provenance sections are distinguished by **section heading + description**, not color: "System templates" rows carry a subtle read-only affordance (muted `text-tertiary` metadata, no edit controls); no separate background tint is introduced.

## Layout & Screens

**Screen 1 — List/management page** (`settings/templates`, admin-only, `SettingsContentWrapper` non-hugging, `max-w-225`):

- Breadcrumb header (`SettingsPageHeader`) with `LayoutTemplate` lucide icon + "Project Templates".
- `SettingsHeading` (title + description) with the `New template` primary button in the `control` slot (mirrors webhooks/labels).
- Two stacked sections separated by `lg` (24px): **System templates** then **Custom templates**, each a `text-h6-medium` heading + `text-body-xs-regular` description followed by its rows.
- Custom section header carries the `Show deactivated` toggle (right-aligned control), off by default (D-06). Deactivated rows render muted (`text-tertiary`, reduced opacity) with a `Reactivate` affordance when revealed.
- Rows: template name (`text-body-sm-medium`) + one-line description/counts (`text-body-xs-regular text-tertiary`), actions right-aligned per D-07/D-08.
- Loading → `Loader` skeleton rows; custom-empty → `EmptyStateCompact`; error → inline error copy with retry.

**Screen 2 — Editor page** (`settings/templates/new` and `settings/templates/:id/edit`, admin-only, full-page per D-09; `SettingsContentWrapper hugging`):

- Header breadcrumb: Project Templates → {New project template | Edit template}.
- Top block: Name (`Input`) + Description (`TextArea`).
- Five sections in fixed order — States, Labels, Modules, Cycles, Starter issues — each modeled on the project-states/labels editors: section heading + `Add {item}` control, then an inline reorderable list of add/edit/remove rows (D-11). Drag handles only where order matters (States, Labels).
- Reference keys are never shown (D-12); starter-issue reference fields are dropdowns populated from items defined above (D-13).
- Single atomic Save (D-10): one `Save template` primary button (+ `Cancel`) submitting the whole payload; on success toast + navigate back to the list. Built-in "View" reuses this editor route in a read-only/disabled mode.

## Interaction & State Contracts

Every surface must define the four canonical states (existing screens set the precedent):

| Surface               | Loading                     | Empty                                                                            | Error                                                        | Success/populated                                       |
| --------------------- | --------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------- |
| List page             | `Loader` skeleton rows      | `EmptyStateCompact` (custom section only; system section always has 3 built-ins) | inline error + retry, non-blocking                           | grouped rows with actions                               |
| Editor sections       | n/a (in-memory)             | per-section hint line                                                            | inline field/row validation from backend + client pre-checks | reorderable populated rows                              |
| Save                  | button spinner + disabled   | n/a                                                                              | error toast + inline field errors, form stays open           | success toast + redirect to list                        |
| Deactivate/Reactivate | button spinner in modal/row | n/a                                                                              | error toast                                                  | row moves section / toggles muted state + success toast |

Client-side guards (surface before round-trip, per Claude's Discretion in D): enforce exactly one default state, constrain group/status/priority to enum selects, validate `#RRGGBB` color, block duplicate names within a section, and enforce `start_offset_days ≤ target_offset_days` on cycles. Backend validation errors still surface inline.

Accessibility: reuse existing focus-ring tokens (`ring-accent-strong`), keyboard-operable menus/dropdowns (Radix-backed), drag handles have accessible labels, color pickers pair color with the text name (color is never the sole differentiator).
