# Phase 01 Plan 01: Persist and expose the read-only built-in template catalog

## One-liner

Wired the first backend catalog slice: a persisted `ProjectTemplate` model with idempotent built-in seed, strict JSON payload validation, and a workspace list API that returns the three built-in templates to admins and members while denying guests.

## What Was Built

### Persistence and seed

- `apps/api/plane/db/models/project_template.py` introduces `ProjectTemplate` inheriting `BaseModel` (which extends `AuditModel`). Nullable `workspace` FK, `template_type` (BUILT_IN/CUSTOM), `system_key` (SlugField), `is_system`, `is_active`, and `payload = models.JSONField(default=dict)` per D-01/D-09/D-10. Two DB constraints enforce a unique global `system_key` for built-ins and a unique active name per workspace for customs (D-12), so the seed migration can re-run safely and custom copies are never overwritten.
- `apps/api/plane/db/migrations/0122_projecttemplate.py` is generated by Django and then extended with `seed_builtin_project_templates` and `reverse_seed_builtin_project_templates`. The seed syncs by stable `system_key` (`software-project`, `marketing-campaign`, `operations-project`) and writes global rows with `workspace=None` and `is_system=True` so list endpoints can union built-ins and custom templates in one query.

### Payload validation

- `validate_project_template_payload` in `apps/api/plane/app/serializers/project_template.py` enforces the strict payload contract from D-01..D-04 and CUST-04..CUST-08:
  - Required `schema_version` (currently `PROJECT_TEMPLATE_SCHEMA_VERSION = 1`).
  - Unique `state_key`, `label_key`, `module_key`, `cycle_key`; exactly one state has `default=True`.
  - Hex color format, allowed `group` (state), `status` (module), and `priority` (issue) enum values.
  - Dangling reference checks: starter issues must point to known state/label/module/cycle keys.
  - Optional module/cycle integer `start_offset_days` / `target_offset_days` / `duration_days` are type-checked (must be int, not bool) and order-checked (`start <= target`). Phase 2 will interpret these values during project creation.
- Errors are accumulated into a list and raised as a single `ValidationError` so callers surface every problem at once.

### Serializers

- `ProjectTemplateSerializer` (read) exposes `id`, `name`, `description`, `template_type`, `system_key`, `is_system`, `is_active`, `payload`, `workspace` (null for built-ins, UUID string for customs), `start_offset_days`, `target_offset_days`, `duration_days`, `created_at`, `updated_at`.
- `ProjectTemplateWriteSerializer` runs `validate_project_template_payload` and rejects `is_system=True` / non-null `system_key` attempts. `create` injects `workspace_id` from the request context, `is_system=False`, and `system_key=None` to make built-in creation impossible through the API.
- `ProjectTemplateDuplicateSerializer` is declared as the placeholder shape that Plan 02 will use when wiring the duplicate endpoint.

### Workspace API

- `WorkspaceProjectTemplateViewSet` in `apps/api/plane/app/views/workspace/project_template.py` inherits `BaseViewSet`. `get_queryset` returns the union of active global built-ins and active workspace-scoped custom templates; `list` uses `@allow_permission(allowed_roles=[ROLE.ADMIN, ROLE.MEMBER], level="WORKSPACE")` so guests receive the standard 403 from the existing permission helper.
- The route `workspaces/<str:slug>/project-templates/` is registered in `apps/api/plane/app/urls/workspace.py` with name `workspace-project-templates` and maps `{"get": "list"}`. Write methods are intentionally not registered in Phase 1; Plan 02 will add admin-only `POST/PATCH/DELETE/duplicate`.

### Tests

- 19 unit tests across `TestProjectTemplateSerializer` (15) and `TestProjectTemplateModel` (4) cover payload validation, model constraints, default values, and write serializer behavior.
- 6 contract tests in `TestProjectTemplateCatalogAPI` cover admin/member allow, guest 403, payload/metadata fields, workspace-null built-ins, and inactive custom filtering.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Hand-written migration was missing inherited fields**

- **Found during:** Task 2 verification
- **Issue:** The first hand-written `0122_projecttemplate_seed_builtins.py` migration omitted the `deleted_at` field and the proper `auto_now_add`/`auto_now` verbose*name metadata that `BaseModel` (via `AuditModel`) expects. Running `python manage.py makemigrations --check --dry-run` produced a `0123*...\_and_more` migration that altered several fields.
- **Fix:** Deleted the hand-written migration and the auto-generated `0123_...`, then re-ran `makemigrations db --name projecttemplate` to let Django generate the correct schema, then re-appended the `RunPython` seed by hand on top of the generated file.
- **Files modified:** `apps/api/plane/db/migrations/0122_projecttemplate.py`
- **Commit:** 6ff6a3ac0

**2. [Rule 1 - Bug] Write serializer did not persist workspace**

- **Found during:** Task 2 unit test run
- **Issue:** `ProjectTemplateWriteSerializer.save()` produced a row with `workspace_id=None` even when the request carried a valid `workspace_id` in context. The unit test `test_write_serializer_creates_template_with_valid_payload` failed on the assertion `instance.workspace_id == workspace.id`.
- **Fix:** Added a `create()` method on `ProjectTemplateWriteSerializer` that pulls `workspace_id` from `self.context` and forces `is_system=False` and `system_key=None` so the API can never create a built-in row.
- **Files modified:** `apps/api/plane/app/serializers/project_template.py`
- **Commit:** 6ff6a3ac0

**3. [Rule 1 - Bug] Contract tests used wrong BUILT_IN_PROJECT_TEMPLATES shape**

- **Found during:** Task 3 contract test run
- **Issue:** The first contract test draft referenced `session_client.__class__()` (undefined name) and assumed `BUILT_IN_PROJECT_TEMPLATES` entries put `name` inside a `payload` subdict instead of at the top level. Pytest's `--nomigrations` setting also meant the seed migration never ran, so even after the structure fix the list endpoint returned an empty set.
- **Fix:** Replaced `session_client.__class__()` with `rest_framework.test.APIClient()`; corrected the expected name set to read `t["name"]` from the top level; and added a `seeded_builtin_templates` pytest fixture that mirrors the migration's `update_or_create` so contract tests populate the global built-ins independently of the migration runner.
- **Files modified:** `apps/api/plane/tests/contract/app/test_project_templates_app.py`
- **Commit:** 14e3aebfa

## Auth Gates

None. All authentication and authorization behavior was verified through local contract tests against the existing `allow_permission` helper and `BaseSessionAuthentication` stack; no human sign-in was required.

## Known Stubs

- `ProjectTemplateDuplicateSerializer` is intentionally a placeholder for Plan 02 to wire the duplicate endpoint against `WorkspaceProjectTemplateViewSet.duplicate`. It exposes only a `name` field; no business logic yet.
- Optional module/cycle integer date metadata fields are persisted but not yet interpreted; Phase 2 will apply them during project creation.

## Threat Flags

No new threat surface beyond what the plan's threat register already covers. `WorkspaceProjectTemplateViewSet.list` only exposes active global built-ins and active workspace custom templates through the existing `BaseSessionAuthentication` + `allow_permission` path; the seed migration only writes to rows with `is_system=True, workspace_id IS NULL` so custom copies are never touched.
