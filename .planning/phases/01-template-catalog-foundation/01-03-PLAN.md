## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| serializer validation -> future project creation | Template payloads saved now will be consumed by Phase 2 transaction logic. |
| workspace API -> database rows | Detail/write UUIDs can target rows outside the intended workspace or system catalog if guards are weak. |
| role permission -> reusable workspace setup | Unauthorized writes can alter workspace-wide setup presets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-08 | Tampering | `validate_project_template_payload` | high | mitigate | Hardening tests and deterministic validation reject malformed payloads before persistence. |
| T-01-09 | Information Disclosure | detail/write lookup behavior | medium | mitigate | Write/detail lookups are workspace-scoped and custom-only; cross-workspace rows return 404. |
| T-01-10 | Elevation of Privilege | write endpoints | high | mitigate | Contract tests prove member and guest writes return standard 403 responses across all write methods. |
| T-01-11 | Denial of Service | payload size and structure | low | accept | Phase 1 uses structured payload validation; broader request-size controls are already handled by existing Django middleware/settings. |
| T-01-SC | Tampering | package installs | low | accept | No npm, pip, or cargo package installs are planned for this phase. |
</threat_model>
