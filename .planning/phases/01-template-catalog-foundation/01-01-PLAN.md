## Phase Goal

**As a** workspace user, **I want to** access built-in and custom Project Templates through the backend catalog, **so that** later project creation can select a validated ready-to-work structure.

<objective>
Create the first backend catalog slice: a persisted ProjectTemplate model, idempotent built-in seed records, strict payload validation helpers, and a workspace list API that exposes built-ins to admins and members while rejecting guests.

Purpose: prove the catalog foundation end-to-end before write lifecycle expansion.
Output: model, migration, serializers, workspace API route, and tests for built-in listing and payload validation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client -> workspace catalog API | User-controlled workspace slug and API request cross into DRF viewset code. |
| serializer -> database | JSON payload and template metadata cross from request validation into persisted rows. |
| migration seed -> database | Built-in catalog data is written as global system records. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `validate_project_template_payload` | high | mitigate | Strict serializer/helper validation rejects invalid payload shape, enum values, duplicate keys, and dangling references before save. |
| T-01-02 | Information Disclosure | `WorkspaceProjectTemplateViewSet.list` | medium | mitigate | List query combines only active global built-ins and active custom templates scoped to `workspace__slug=slug`; guest access is denied. |
| T-01-03 | Tampering | `seed_builtin_project_templates` | medium | mitigate | Migration syncs only rows with stable system keys, `is_system=True`, and `workspace=None`, preventing custom-copy updates. |
| T-01-SC | Tampering | package installs | low | accept | No npm, pip, or cargo package installs are planned for this phase. |
</threat_model>
