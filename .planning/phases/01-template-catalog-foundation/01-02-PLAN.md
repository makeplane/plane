## Phase Goal

**As a** workspace admin, **I want to** create and manage custom Project Templates through the backend API, **so that** my workspace can maintain reusable project structures without mutating system built-ins.

<objective>
Expand the catalog from read-only built-ins to the custom workspace template lifecycle: admin-only create, edit, deactivate, and duplicate-built-in-to-custom APIs.

Purpose: make workspace custom templates usable and permissioned while preserving built-in immutability.
Output: write serializers/view methods/routes and contract tests for custom lifecycle behavior.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client -> write API | User-controlled metadata and payload cross into create/update/duplicate/deactivate handlers. |
| workspace role -> mutation boundary | Workspace role membership determines who can change reusable templates. |
| built-in row -> custom copy | Global read-only template data is copied into a workspace-scoped mutable record. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Elevation of Privilege | `WorkspaceProjectTemplateViewSet.create/partial_update/destroy/duplicate` | high | mitigate | Use `allow_permission([ROLE.ADMIN], level="WORKSPACE")` and contract tests for member/guest 403. |
| T-01-05 | Tampering | custom write queryset | high | mitigate | PATCH/DELETE lookups filter to `workspace__slug=slug, is_system=False`; built-in rows cannot be updated through custom routes. |
