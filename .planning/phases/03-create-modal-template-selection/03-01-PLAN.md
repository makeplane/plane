## Phase Goal

**As a** workspace member who can create Projects, **I want to** select and preview a Project Template in the existing create Project modal, **so that** the create request can apply the chosen template without changing the normal no-template flow.

<objective>
Deliver the happy-path vertical slice for Phase 03: the create Project modal can fetch available templates, show them in the existing compact cover-header selector, let the user choose or clear a template, and submit template_id only when selected.

Purpose: connect the Phase 01 catalog endpoint and Phase 02 optional template_id backend contract to the existing frontend create modal while preserving D-01 through D-12 and D-18 through D-22.
Output: frontend template contracts, service/store typing, compact selector UI, local form state, modal-open reset behavior, and submit payload wiring.
</objective>

<threat_model>

## Trust Boundaries

| Boundary                            | Description                                                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Browser -> Plane API                | Template catalog fetch and Project create submit cross from untrusted browser state into authenticated API routes. |
| API data -> React render            | Template names/descriptions returned from the API are rendered inside the dropdown.                                |
| Modal-local state -> create payload | Selected template state is merged into the Project create request.                                                 |

## STRIDE Threat Register

| Threat ID | Category               | Component                               | Severity | Disposition | Mitigation Plan                                                                                                                                                                |
| --------- | ---------------------- | --------------------------------------- | -------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T-03-01   | Tampering              | `CreateProjectForm` submit payload      | medium   | mitigate    | Submit only the selected catalog item's backend-provided `id` and keep backend Phase 02 availability validation authoritative; do not add client-side role/template filtering. |
| T-03-02   | Information Disclosure | `ProjectTemplateSelect` error rendering | medium   | mitigate    | Render generic inline catalog failure copy in the selector and avoid exposing HTTP status, permission role, or template availability details.                                  |
| T-03-03   | Elevation of Privilege | Template catalog access                 | medium   | transfer    | Backend Phase 01 `allow_permission` enforces admin/member catalog access; frontend uses the service endpoint and handles denial as an inline load error.                       |
| T-03-04   | Cross-Site Scripting   | Template description row                | medium   | mitigate    | Render template name and description as plain React text, never as HTML or markdown.                                                                                           |
| T-03-SC   | Tampering              | npm/pip/cargo installs                  | high     | mitigate    | No package-manager install tasks are allowed in this plan; use existing catalog/workspace dependencies only.                                                                   |

</threat_model>
