<!-- Reference for transaction.on_commit semantics (RESEARCH Pitfall 2 / Pitfall 9) -->
- Inside `with transaction.atomic():`, `transaction.on_commit(callable)` registers the callable to fire ONLY when the outer atomic block commits.
- On rollback (uncaught exception inside the block), all registered callbacks are silently DISCARDED — they never run. This is the desired Pitfall 7 regression guard.
- pytest.mark.django_db wraps each test in a transaction that NEVER commits. So in a test, callbacks registered via `transaction.on_commit(...)` will NOT fire by default. To assert "callback was registered", patch `transaction.on_commit` with `side_effect=lambda fn: fn()` (RESEARCH Pitfall 9).

       actor_id_str = str(request.user.id)
       project_id_str = str(project_id)

       # Per-pair issue_activity.delay (mirrors views/issue/base.py:1141-1166 shape,
       # wrapped in on_commit per CONTEXT D-09). Log start_date and target_date as
       # SEPARATE events when both move; skip the event if the field didn't change.
       for inst in instances:
           pre = pre_update_snapshot[inst.id]
           if inst.start_date != pre.start_date:
               transaction.on_commit(
                   lambda inst=inst, pre=pre: issue_activity.delay(
                       type="issue.activity.updated",
                       requested_data=json.dumps(
                           {"start_date": str(inst.start_date)},
                           cls=DjangoJSONEncoder,
                       ),
                       current_instance=json.dumps(
                           {"start_date": str(pre.start_date)},
                           cls=DjangoJSONEncoder,
                       ),
                       issue_id=str(inst.id),
                       actor_id=actor_id_str,
                       project_id=project_id_str,
                       epoch=epoch,
                   )
               )
           if inst.target_date != pre.target_date:
               transaction.on_commit(
                   lambda inst=inst, pre=pre: issue_activity.delay(
                       type="issue.activity.updated",
                       requested_data=json.dumps(
                           {"target_date": str(inst.target_date)},
                           cls=DjangoJSONEncoder,
                       ),
                       current_instance=json.dumps(
