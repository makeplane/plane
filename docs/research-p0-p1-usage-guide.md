# Plane for AI4MS 科研管理 P0 / P1 使用说明

面向使用者的操作手册，覆盖 P0（组织与报告）与 P1（阶段、评审、实验、代码、集成）全部已交付功能。
实现依据见 [`research-p0-development-prd.md`](./research-p0-development-prd.md) 与
[`research-p1-development-prd.md`](./research-p1-development-prd.md)，发布与回滚口径见对应的 release notes。

## 2. 首次使用：按这个顺序初始化

1. **平台配置**（管理员，`/research/settings/platform`）
   确认「为本工作区启用科研模块」已勾选，并按需打开组织架构 / 周期报告 / 办公审批；
   设置报告默认可见级别、科研上传限制、审计保留天数。
   启用模块时会自动创建组织树根节点。
2. **组织架构**（管理员，`/research/settings/org`）
   根节点 → 逐级添加学院 / 实验室 / 课题组 / 小组；选中节点后在「成员与角色」里添加成员（节点负责人 / 课题组主 PI /
   导师 / 评审人 / 组织管理员），在「直接导师」里绑定「科研责任人 → 导师」。
   **报告验收、阶段评审的必评人、可见范围里的「直接导师」全部来自这两处配置。**
3. **身份映射**（可选，`/research/settings/identity`）把 AI4MS OIDC 的 `sub` 绑定到本地账号；未配置 OIDC 时继续用本地邮箱 + 密码登录。
4. **科研项目**（`/research/projects`）
   填「科研责任人邮箱或 ID」（留空=本人）并选类型（博士 / 硕士 / 博士后 / 科研项目）→ 创建科研项目。
   默认一人一个进行中项目；归档后可在列表恢复；确需多个时在平台配置里打开「允许一个责任人存在多个进行中项目」。

> 顺序上的硬依赖：**没有进行中的科研项目，就创建不了报告**；`科研阶段` 也要先有项目才能初始化。

## 3. P0 功能怎么用

### 3.1 周报 / 月报（报告页 `/research/reports`）

1. 选类型（周报 / 月报）+ 周期（如 `2026-W38`、`2026-09`，留空=当前周期）→「创建报告」。
   同一周期同一类型只能有一份；周期早于当前周期会自动标记「补交」。创建时可套用报告模板。
2. 进入报告详情 →「打开正文」跳到页面编辑器写正文（正文是一个 Page，走编辑器全部能力）。
3. 「可见范围」在详情页切换：仅本人 / 直接导师 / 本组织节点 / 上级节点主 PI / 工作区全员 / 自定义授权。
   **只能在工作区默认级别基础上收窄，不能扩大**。
4. 「附件与正文导入」：上传 PDF；选 `.md` 文件「导入为正文」（标题、列表、代码块、表格结构保留，本地图片引用会提示手工替换）。
5. 流转：作者点「提交」→ 直接导师 / 被指派评审人 / 工作区管理员可「验收」；需要修改时点「退回」并填写原因（必填）。
   退回后报告回到可编辑状态，作者改完重新提交。所有动作都记录在「审核历史」里。

### 3.2 提交汇总（`/research/reports/summary`）

按组织节点 + 周期查看提交情况，并列出「未提交名单」。统计口径是「拥有进行中科研项目的成员」。

### 3.3 办公审批（`/research/approvals`）

- **审批流配置**（页面下方）：新增审批流，设置名称、审批类型（任务 / 采购 / 自定义）、级数与每级审批人、或签 / 会签。
- **发起审批**：当前版本没有界面入口，通过接口发起：

  ```http
  POST /api/research/workspaces/fangyikai/approval-requests/
  {
    "issue": "<工作项 ID>",
    "approval_type": "PURCHASE",
    "org_unit": "<组织节点 ID>",
    "flow": "<审批流 ID>"
  }
  ```

- **处理**：切到「待我审批」→「通过」或「驳回」（驳回必须写原因）；发起人可在「我发起的」里「撤回」；「已完成」查看历史。
- 约束：一个工作项只能有一条审批；审批只推进状态，不改写工作项自身的历史。

### 3.4 审计记录（`/research/audit`）

只读、只追加的科研操作记录，可按操作与资源类型筛选。界面不提供编辑、删除、导出。

## 4. P1 功能怎么用

从 `/research/projects` 点开自己的科研项目后，顶部会出现项目内标签页：
**科研阶段 / 文献调研 / 实验条目 / 代码管理 / 论文与成果 / 时间线**（子开关关闭的标签不显示）。

### 4.1 科研阶段（项目 → 科研阶段）

四个固定阶段：预开题 → 开题 → 中期 → 结题。典型动作顺序：

1. 「初始化阶段」建出四个阶段实例（只做一次）。
2. 对当前阶段点「进入阶段」，此时可以编辑材料。
3. 「材料清单」按阶段固定（预开题 2 项、开题 10 项、中期 7 项、结题 7 项），逐项「创建」→「在页面编辑器中打开」写内容 →「提交材料」。
   材料提交后只读，阶段被退回后可再次编辑；管理员可用「代改材料」应急修改，代改会留痕并写审计。
   （门槛判定看的是材料条目是否存在，草稿状态也计入齐备；「提交材料」用于把内容冻结成版本。）
4. 点「提交评审」前先看「门槛检查清单」（提交前校验项）：

   | 阶段   | 提交前门槛（默认值）                                                                        |
   | ------ | ------------------------------------------------------------------------------------------- |
   | 预开题 | 材料齐备（2 项）+ 纳入文献 ≥ 20 篇 + 文献登记总数不超 100 + 每条纳入文献都有摘要与 gap 笔记 |
   | 开题   | 材料齐备（10 项）+ 至少 1 条实验记录 + 至少 1 个代码仓库                                    |
   | 中期   | 材料齐备（7 项）+ 至少 1 条已完成实验 + 所有未完成实验都有状态说明                          |
   | 结题   | 材料齐备（7 项）+ 成果登记数量达标 + 实验记录总表 + 代码快照已归档 + 导师评审意见材料       |

   门槛未满足时条目会标红并给出补充提示；被阻塞时无法提交。

5. 提交后进入评审（见 4.2），评审人在「待我评审」里给出意见。
6. 「通过阶段」时还要过「通过前校验」的评审规则：直接导师必须评过、主 PI（或授权评审人）必须覆盖、
   有效评审人数 ≥ 3、通过比例 > 50%；**直接导师一旦否决，该阶段不通过**。
7. 「退回」必须填原因，原因写入流转记录且事后不可修改；前一阶段未通过不能进入下一阶段；
   同一时间只能有一个阶段处于进行中；管理员可「重开阶段」（结题重开需二次确认），全程留痕。

### 4.2 待我评审（`/research/reviews`）

- 「待我评审」列出指派给你的阶段；点「进入阶段」可看材料与门槛清单，然后「提交评审」：
  结论选通过 / 否决 / 退回修改，可填 0-100 分评分与意见（**否决与退回必须填意见**）。
- 「我的评审」可「修改评审」，每次修改保留历史版本，可填写修改原因。
- 需要时对未提交的评审人点「催办」。

### 4.3 文献调研（项目 → 文献调研）

- 「登记文献」：标题、DOI、期刊 / 会议、年份、摘要、gap 笔记。
- 「批量导入」：DOI 列表（每行一条，可在 `|` 后补标题）或粘贴 BibTeX；导入结果显示成功 / 跳过 / 失败条数。
- 状态流转：已收集 → 已筛选 → 已纳入 / 已排除。**纳入必须同时填摘要与 gap 笔记**，否则「纳入文献信息完整」这一门槛不通过。
- 顶部实时显示「已纳入 x / 需 20」「已登记 x / 上限 100」，重复 DOI 会被拒绝。

### 4.4 实验条目（项目 → 实验条目）

1. 「登记实验」填标题 → 在右侧详情补充分子体系、实验 / 计算方法、参数、环境、假设等。
2. 「开始运行」后，分子体系、方法、参数、环境、开始时间等关键字段被锁定（保证事实不可事后改写）。
3. 「标记完成」或「标记失败」；未完成的实验必须写状态说明（中期门槛会检查）。
4. 「提交」后记录只读。需要修改时「发起修订」：填原因、只改允许修订的字段，核准后追加新版本，
   旧版本永久保留；同一实验同时只能有一条待审核修订。
5. 设备 / 外部系统回传的实验会带来源标记，未同步的部分显示「待补（源系统未同步）」。

### 4.5 代码管理（项目 → 代码管理）

「登记仓库」（仓库地址 + 提供方 GitHub / GitLab / Gitea / 本地 git）→「同步」查看最近提交（失败会显示同步失败）→
「登记版本引用」（commit SHA / 分支 / tag）→「上传快照」（默认单包上限 500MB）→ 可把制品关联到具体实验。

### 4.6 论文与成果（项目 → 论文与成果）

「登记成果」填名称、类型（论文 / 专利 / 软件 / 数据集 / 获奖 / 其他）、期刊或授予单位、DOI 或专利号、
状态（草稿 → 已提交 → 已录用 → 已发表）；「导出引用清单（Markdown）」导出只含引用信息的清单。

### 4.7 时间线（项目 → 时间线）

在「思维链 / 研发链 / 全部」之间切换，按阶段与来源系统筛选，查看文献、阶段流转、阶段评审、周报月报、
实验记录、代码制品、成果与外部引用的完整时间轴；外部系统不可用时会标注「降级来源」，并可「导出引用清单（Markdown）」。

### 4.8 系统集成（管理员，`/research/integrations`）

1. 「连接配置」按系统（RAGPortal、WeKnora、SpecLabOS、SmartAccess、Poly_Agent、Spec_Agent）维护：
   展示名、`base_url`、认证方式（HMAC / Bearer / OIDC 客户端凭证 / 无）、**凭证引用名**、超时、缓存 TTL、降级模式、启用开关。
   凭证只保存「引用名」，明文放在后端环境变量或密钥管理系统（`<SYSTEM>_AUTH_SECRET`）。
2. 健康检查显示 未配置 / 正常 / 降级 / 不可用；「检索并引用外部对象」可搜索知识条目、运行记录、数据资产、
   研发项目与结果并「引用该条目」，也可「在源系统打开」。
3. 源系统不可用时按降级模式退回链接展示，页面顶部给出降级提示；下方「集成调用日志」记录操作、结果、耗时与错误码。

### 4.9 中期进展汇总

中期阶段页内的「进展汇总」面板只读引用源数据：实验已完成 x/y、代码仓库与制品数量、纳入文献数、
周期内报告数，并提示还有多少条未完成实验缺少状态说明。修改要回到对应页面，汇总本身不可编辑。

## 5. 一条完整流程（从开题到结题）

1. 管理员：组织架构建「学院 → 课题组」，把学生加入课题组，并在「直接导师」里绑定「学生 → 导师」。
2. 学生：创建个人科研项目（类型=博士）。
3. 项目 → 文献调研：批量导入 DOI，筛选并纳入 ≥ 20 篇，逐条补摘要与 gap 笔记。
4. 项目 → 科研阶段：初始化 → 进入预开题 → 填 2 份材料 → 门槛检查 → 提交评审。
5. 导师：待我评审 → 提交评审；另有 ≥ 3 位有效评审且过半数通过后，学生（或管理员）点「通过阶段」。
6. 进入开题：先登记 ≥ 1 个代码仓库与 ≥ 1 条实验记录，再补齐 10 份材料 → 提交 → 评审 → 通过。
7. 期间：实验条目持续登记（开始运行 → 完成 / 失败），代码管理登记版本引用并上传快照。
8. 每周：报告页创建周报 → 打开正文撰写 → 提交 → 导师验收或退回。
9. 中期：至少完成 1 条实验、未完成实验写清说明 → 填 7 份材料 → 提交评审 → 通过。
10. 结题：登记论文 / 成果、上传代码快照与导师评审意见材料 → 填 7 份材料 → 提交评审 → 通过。
11. 全程可随时看「时间线」与「审计记录」，并导出引用清单用于结题材料。

## 6. 已知限制与注意事项

- 报告**正文内嵌图片**仍走全局 `FILE_SIZE_LIMIT`（5MB）；报告**附件**走科研独立限制（默认图片 20MB / PDF 100MB / Markdown 5MB）。
- 发起审批目前只有接口，没有界面按钮。
- P1 的四个子开关（阶段 / 实验 / 代码 / 集成）与门槛数值（文献 20 / 100、评审 3 人、通过比例 50%、快照 500MB）
  目前只在数据库 `workspace_research_settings` 与部署环境变量里，界面暂未暴露；默认全部开启。
- 审计只提供查询，不提供导出与自动清理；`research_audit_events` 在模型层禁止更新与删除。
- Markdown 导入的本地图片需手工上传替换，远程图片保留外链。
- 科研对象不进入全局搜索索引，搜索里找不到属预期行为。
- 外部系统凭证只以引用名入库，接口只回显「是否已配置」。
- **登录提交报 `CSRF Verification Failed`**：后端只信任 `apps/api/.env` 里
  `CORS_ALLOWED_ORIGINS` + `CSRF_TRUSTED_ORIGINS` 登记的来源，用没登记的 IP / 主机名打开页面时，登录表单 POST 会被 Django 拒绝。
  处理方式：① 把该地址补进 `CSRF_TRUSTED_ORIGINS` 后执行
  `docker compose -f docker-compose-local.yml -f docker-compose-local.override.yml up -d --no-deps api`；
  ② 开发态三个 Vite 代理已改为保留浏览器 Host（`changeOrigin: false`），重启 `web / admin / space` 启动进程即可用任意地址访问。
  排查：`docker compose -f docker-compose-local.yml -f docker-compose-local.override.yml logs api | grep "CSRF verification failed"`，
  日志会打印被拒原因（来源不匹配 / 缺少 cookie / token 失效）。
