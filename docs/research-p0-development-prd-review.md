## 3. 结论摘要

1. **需求编号完整且可追溯**。共 89 条需求：ORG 9、ID 8、ACL 10、CFG 8、AUD 6、PRJ 8、RPT 12、FILE 8、APR 7、UI 8、COMPAT 5；§3 需求表与 §13 验收清单逐条对应，无孤立编号、无重复编号。
2. **阶段划分可执行**。10 个阶段的工作量合计 108 人日，与 §8 排期表（9–10 周）自洽；阶段依赖无环（A1 → A2/A3 → A4 → B1 → C1 → C2/C3 → D1 → E1）。
3. **模型与接口总体可实现**，但有 9 处文档内部不一致、11 处需在实现层固化技术决策，已在 §4、§5 给出处理结论。
4. **最大风险不在功能，而在兼容**：科研 ACL、报告只读、文件限制三处必然触碰既有代码路径，均已给出"最小侵入点 + 短路放行"方案（§5 T-08、T-11，§6 G-08）。
5. **待确认事项不阻塞开发**：§12 的 12 项业务待确认事项全部给出"P0 实施默认值"，可在业务确认后通过配置或文案调整收敛，无需改动数据模型主干（§7）。

## 5. 技术风险与实现层固化决策（T 类）

| 编号 | 风险/约束                                                                                                                   | 处理决定                                                                                                                                                                                           |
| ---- | --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-01 | `UniqueConstraint(workspace, parent, name)` 在 `parent IS NULL` 时不生效（SQL 中 NULL 互不相等），根节点可重名              | 追加部分唯一约束 `UniqueConstraint(fields=["workspace","name"], condition=Q(parent__isnull=True))`，并保留原约束覆盖非根节点                                                                       |
| T-02 | "同一用户在同一 Workspace 只有一个 `is_primary`" 无法用单表唯一约束表达（Workspace 需经 `org_unit` 关联）                   | `OrgUnitMember` 冗余 `workspace` 字段（新表新增字段，无兼容影响），并建立条件唯一约束；写路径同时做应用层校验                                                                                      |
| T-03 | `PeriodicReport.page` 声明 `on_delete=PROTECT`，会阻断既有 Page 删除路径，与 P0-COMPAT-01 冲突                              | FK 改为 `CASCADE`（避免阻断既有删除）；同时在既有 Page 删除入口加"报告正文保护"判断：已提交报告正文拒绝普通删除并写审计                                                                            |
| T-04 | 审计表对 Workspace 使用 `PROTECT`，Workspace 硬删除会被阻断                                                                 | 保留 `PROTECT`（审计不随业务消失是本需求的核心）；P0 不提供 Workspace 硬删除入口，运维执行硬删除前需先归档审计，写入 §10 发布说明                                                                  |
| T-05 | §4.6 要求"数据库层回收审计表 UPDATE/DELETE 权限"，但开发/测试环境共用单一 DB 账号，迁移无法完成该动作                       | P0 交付"模型层强制（`save` 拒改、`delete` 抛错、QuerySet 拦截）+ 迁移内注释形式的生产 SQL 说明"；权限回收作为部署步骤记录在 §10，不进入自动化迁移                                                  |
| T-06 | 新增 `/api/research/` 与既有 `path("api/", ...)` 前缀的注册顺序                                                             | 将 `api/research/` 注册在 `api/` 之前，规避前缀抢占；同时保证既有路径完全不动                                                                                                                      |
| T-07 | `ReportAccessGrant` 的"用户与组织节点二选一"必须落到数据库层                                                                | 使用 `CheckConstraint`（异或）表达；软删除/撤销用 `is_revoked`，不物理删除                                                                                                                         |
| T-08 | 报告只读要求"普通 Page 接口不得成为旁路"（P0-ACL-08、P0-RPT-07），必须侵入既有 Page 视图                                    | 新增 `plane/research/utils/page_guard.py`，在既有 Page 更新/删除入口调用单一短路函数：非科研报告 Page 直接返回放行，不改变原语义；命中时按状态与角色判定                                           |
| T-09 | OIDC 需校验 `state`/`nonce`/`id_token` 签名与时钟偏移                                                                       | 复用既有 `OauthAdapter` 结构，JWKS 按 issuer 缓存并定时刷新，`state`/`nonce` 存服务端会话，时钟偏移容错 ±120s                                                                                      |
| T-10 | 科研通知复用既有 `Notification`，前端通知中心对未知 `entity_name` 无渲染分支                                                | 后端使用 `research_report` / `research_approval` 作为 `entity_name`；前端补兜底分支，未知类型按通用文本渲染，不报错                                                                                |
| T-11 | `DATA_UPLOAD_MAX_MEMORY_SIZE` 复用 `FILE_SIZE_LIMIT`（5MB），科研 20MB/100MB 上传会被中间件/内存上限拦截                    | 科研上传不走服务端整体缓冲：沿用既有 S3 直传签名链路，服务端只做签名前校验与上传后登记；不修改 `FILE_SIZE_LIMIT` 与 `DATA_UPLOAD_MAX_MEMORY_SIZE`                                                  |
| T-12 | §5 接口路径写作 `/api/research/org-units/`，未携带 Workspace 维度，而既有 `plane.app` 全部采用 `workspaces/<slug>/...` 前缀 | 统一为 `/api/research/workspaces/<slug>/<资源>/`，与既有风格一致、可直接复用既有 Workspace 权限中间件与前端 SDK 约定；`/api/research/health/`、`identity`、`audit` 等跨 Workspace 资源保留全局路径 |
| T-13 | 审计模型被排到 P0-A4（迁移 0126），但 P0-ORG-09 属 P0-A1 需求且为 A1 必测项                                                 | 将 `ResearchAuditEvent` 随 A1 一并交付（迁移 0123），A1 落地审计"只追加"底座；A4 聚焦配置、模板与审计查询接口，需求编号归属不变                                                                    |
