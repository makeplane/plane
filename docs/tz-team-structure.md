# ТЗ: команды, портфели, типы задач и доска управляющей команды

Статус: черновик на вычитку, версия 0.5 от 25.11.2026.

**Как читать.** Пометка **[Решено]** означает ваш ответ или прямое требование. **[Предлагаю]** означает моё предположение, его можно свободно менять. Решения по вопросам собраны в разделе 14.

## 1. Контекст и цель

Сейчас в Plane структура плоская: рабочее пространство → проекты → задачи. Нет уровня команд и портфелей, все задачи одного вида, руководство не видит общей картины по результатам.

Нужно:

1. Ввести структуру «команда → портфель → проект».
2. Дать каждой команде своего админа и открыть работу команд для чтения остальным.
3. Разделить записи в проекте на Задачи, Встречи и Продукты.
4. Собрать продукты всех команд с таймлайнами и статусами на одной доске для управляющей команды.

## 2. Термины

| Термин               | Значение                                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Рабочее пространство | Вся организация (Workspace)                                                                                      |
| Команда              | Подразделение со своими админами, участниками и портфелями                                                       |
| Обычная команда      | Ведёт портфели и проекты, её продукты попадают на доску                                                          |
| Управляющая команда  | Смотрит доску продуктов всех обычных команд и меняет на ней даты, статус, ручной процент и комментарий к статусу |
| Портфель             | Группа проектов внутри одной команды                                                                             |
| Проект               | Существующий проект Plane, входит в один портфель                                                                |
| Задача               | Обычная запись, как сейчас                                                                                       |
| Встреча              | Запись с временем, участниками, повесткой и итогами                                                              |
| Продукт              | Эпик с датами начала и конца и обязательным типом продукта                                                       |
| Тип продукта         | Значение из справочника, например «Датасет»                                                                      |
| Закрытый проект      | Проект, не видимый другим командам (в Plane: network = Secret)                                                   |

## 3. Структура

```
Рабочее пространство
├── Управляющая команда ──► Доска продуктов (просмотр и правка)
├── Команда А (админы, участники)
│   ├── Портфель 1
│   │   ├── Проект 1
│   │   │   ├── Продукт  ← к нему привязаны задачи и встречи
│   │   │   ├── Задача   (можно без продукта)
│   │   │   └── Встреча  (можно без продукта)
│   │   └── Проект 2 (закрытый)
│   └── Портфель 2
└── Команда Б
```

Правила:

- Портфель принадлежит ровно одной команде. **[Решено]**
- Проект входит ровно в один портфель; его команда определяется портфелем. **[Решено]**
- Продукт принадлежит ровно одному проекту; к нему привязываются записи только этого проекта. **[Решено]**
- Задача или встреча относится не более чем к одному продукту. **[Решено]**
- Человек может состоять в нескольких командах. **[Решено]**
- Старые проекты показываются в группе «Без портфеля», пока их не разложат. Новый проект без портфеля создать нельзя. **[Решено]**

## 4. Роли и права

### 4.1. Роли

- **Админ пространства**: создаёт команды, назначает их админов, ведёт справочник типов продуктов, раскладывает текущие проекты по командам, видит закрытые проекты и доску. **[Решено]**
- **Админ команды**: управляет участниками, портфелями и проектами своей команды. Админов может быть несколько, минимум один. **[Решено]**
- **Участник команды**: работает в открытых проектах команды; в закрытых только если добавлен в проект.
- **Участник другой команды**: только читает. **[Решено]**
- **Участник управляющей команды**: читает как все, плюс видит доску и меняет на ней даты, статус, ручной процент и комментарий к статусу продуктов. **[Решено]**
- **Гость пространства**: видит только проекты, куда добавлен явно. **[Решено]**

Роли проекта (Admin, Member, Guest) сохраняются: через них можно добавить в проект человека из другой команды.

### 4.2. Матрица прав

| Действие                                            | Админ пр-ва | Админ команды | Участник команды | Другая команда | Управляющие   |
| --------------------------------------------------- | ----------- | ------------- | ---------------- | -------------- | ------------- |
| Создать или удалить команду                         | да          | нет           | нет              | нет            | нет           |
| Менять карточку команды и участников                | да          | своей         | нет              | нет            | нет           |
| Назначать админов команды                           | да          | своей         | нет              | нет            | нет           |
| Создавать и менять портфели                         | да          | своей         | нет              | нет            | нет           |
| Создавать проекты, менять портфель внутри команды   | да          | своей         | нет              | нет            | нет           |
| Перенести проект в другую команду                   | да          | нет           | нет              | нет            | нет           |
| Читать открытые проекты                             | да          | да            | да               | да             | да            |
| Читать закрытые проекты                             | да          | своей         | если добавлен    | если добавлен  | если добавлен |
| Создавать и менять задачи и встречи                 | да          | своей         | своей            | нет            | нет           |
| Создавать и менять продукты                         | да          | своей         | своей            | нет            | нет           |
| Удалять продукты                                    | да          | своей         | свои             | нет            | нет           |
| Смотреть доску                                      | да          | нет           | нет              | нет            | да            |
| Менять на доске даты, статус, процент и комментарий | да          | нет           | нет              | нет            | да            |
| Вести справочник типов продуктов                    | да          | нет           | нет              | нет            | нет           |

Доску закрыли для всех, кроме управляющей команды **[Решено]**; доступ админа пространства **[Решено]**. Человек с несколькими ролями получает сумму прав. Свои продукты команда меняет в проекте. Управляющие меняют на доске только даты, статус, ручной процент и комментарий; остальные поля чужих проектов для них только для чтения.

### 4.3. Что значит «только чтение»

Доступны: списки, канбан, календарь, таймлайн, карточки, комментарии, вложения, страницы проекта. Недоступны: создание, правка (кроме полей доски у управляющих), комментарии, реакции, перетаскивание, назначение исполнителем. Кнопки скрыты, и **сервер отклоняет запрос независимо от интерфейса**. Экспорт чужих проектов недоступен. **[Решено]**

Закрытый проект не должен выдавать себя другой команде: его нет в списках, поиске, счётчиках, избранном, уведомлениях, и прямая ссылка даёт 403 или 404.

## 5. Команды

Поля: название (уникально в пространстве), описание, иконка, тип (обычная или управляющая), участники с ролями.

- Управляющая команда в пространстве одна. **[Решено]**
- Нельзя снять последнего админа: сначала назначить другого. То же при удалении человека из пространства.
- Архивировать можно команду с портфелями: она исчезает из навигации и с доски, данные остаются. Удалить можно только пустую. **[Решено]**
- Новый участник сразу получает доступ ко всем открытым проектам команды. При уходе теряет доступ, полученный через команду; явно выданный доступ остаётся. Созданные и назначенные ему задачи не меняются.

Страница команды: обзор, портфели, проекты, продукты (список и таймлайн), участники, настройки (для админа).

## 6. Портфели

Поля: название (уникально в команде), описание, иконка, ответственный, порядок. Статус и даты у портфеля в первой версии не вводим. **[Решено]**

- Страница портфеля: список проектов и сводка по продуктам (всего, в работе, просрочено, завершено).
- Архивировать можно в любой момент; удалить можно только пустой портфель.
- Перенос проекта между портфелями своей команды: админ команды. Между командами: админ пространства; доступ участников пересчитывается, перед подтверждением показывается, кто получит и кто потеряет доступ.

## 7. Типы записей

Три системных типа, удалить или добавить свои нельзя. **[Решено]** У всех общий набор Plane: номер, состояние, приоритет, исполнители, метки, комментарии, вложения, история. Тип виден иконкой в списках, карточках, поиске и уведомлениях; по нему есть фильтр и группировка.

### 7.1. Задача

Как сейчас, плюс необязательное поле «Продукт»: задача может жить в проекте отдельно. **[Решено]** Все существующие записи считаются задачами. Подзадачи сохраняются и относятся к продукту через родителя.

### 7.2. Встреча **[Решено: карточка без внешних календарей и повторений]**

| Поле             | Обязательно | Примечание                                          |
| ---------------- | ----------- | --------------------------------------------------- |
| Название         | да          |                                                     |
| Начало           | да          | дата и время с часовым поясом                       |
| Конец            | да          | позже начала                                        |
| Участники        | нет         | пользователи пространства, отдельно от исполнителей |
| Организатор      | да          | по умолчанию автор                                  |
| Место или ссылка | нет         |                                                     |
| Повестка         | нет         | обычное описание записи                             |
| Итоги            | нет         | форматированный текст                               |
| Продукт          | нет         | продукт того же проекта                             |

- Статусы те же, что в проекте; при отмене используется группа «Отменено».
- Показывается в списке и в календаре проекта с временем; время отображается в поясе читателя.
- Участникам приходит уведомление о приглашении, переносе и отмене. Участвовать может только тот, кто видит проект. **[Решено]**
- Из встречи можно создать задачу; она получает тот же продукт и ссылку на встречу. **[Решено]**

### 7.3. Продукт

| Поле                       | Обязательно | Примечание                     |
| -------------------------- | ----------- | ------------------------------ |
| Название                   | да          |                                |
| Тип продукта               | да          | из справочника                 |
| Дата начала, дата конца    | да          | конец не раньше начала         |
| Ответственный              | да          | ровно один                     |
| Состояние                  | да          | из состояний проекта           |
| Описание, метки, приоритет | нет         |                                |
| Ручной процент             | нет         | целое от 0 до 100              |
| Комментарий к статусу      | нет         | короткий текст, виден на доске |
| Прогресс                   | расчётный   | раздел 8                       |
| Индикатор срока            | расчётный   | раздел 8                       |

- Продукт не может иметь родителя и не может быть вложен в другой продукт.
- В карточке продукта: блоки «Задачи» и «Встречи», создание и привязка прямо оттуда, прогресс.
- Если срок задачи выходит за даты продукта, показывается предупреждение, сохранение не блокируется. **[Решено]**
- Завершение с открытыми задачами: предупреждение, без запрета. **[Решено]**
- Удаление **не удаляет** задачи и встречи, а только отвязывает их.
- Смена типа: «задача ↔ встреча» разрешена, если заполнены обязательные поля. Превращение в продукт разрешено записи без родителя; обратно только без привязанных записей. Заполненные поля прежнего типа сохраняются скрытыми. **[Решено]**

### 7.4. Типы продуктов

Единый справочник пространства: название, иконка, цвет, порядок, признак активности. Используемый тип нельзя удалить, только отключить: он остаётся у старых продуктов, но не предлагается для новых. **[Решено]**

- Начальный список: Аналитическая презентация, Аналитическая записка, Датасет. **[Решено]**
- У каждого типа есть своя страница с требованиями к продукту (форматированный текст). **[Решено]** Её читают все сотрудники, кроме гостей, а правит админ пространства; ссылка есть в карточке продукта и при выборе типа. **[Предлагаю]**
- Перечень и требования админ пространства редактирует в настройках пространства. **[Решено]**

## 8. Статус, прогресс и сроки продукта

- **Статус** ставит вручную команда в проекте или управляющие на доске, всегда из состояний этого проекта. **[Решено]** На доске он приводится к общей группе Plane, чтобы команды можно было сравнивать: Бэклог, Не начато, В работе, Завершено, Отменено. Рядом видно название состояния в проекте.
- **Расчётный прогресс** = завершённые задачи / все задачи продукта, кроме отменённых. Подзадачи и встречи не считаются, архивные задачи считаются. Без задач показывается прочерк. **[Решено]**
- **Ручной процент** можно указать дополнительно **[Решено]**. Если он заполнен, он становится итоговым прогрессом, а расчётный показывается рядом; если пуст, берётся расчётный. Итоговый прогресс используется в заливке, таблице и индикаторе. Менять можно в проекте и на доске; очистка поля возвращает расчётный прогресс. **[Решено]**
- **Комментарий к статусу**: одно текущее значение до 500 знаков, с автором и датой правки; меняется в проекте и на доске, прежние значения остаются в истории продукта. Пишут и команда, и управляющие. **[Решено]**
- **Индикатор срока** **[Решено]**, проверяется сверху вниз:

| Индикатор          | Условие                                                                                       |
| ------------------ | --------------------------------------------------------------------------------------------- |
| Завершён / Отменён | по группе состояния                                                                           |
| Просрочен          | дата конца раньше сегодня                                                                     |
| Под риском         | есть просроченные открытые задачи, или до конца не больше 7 дней и итоговый прогресс ниже 80% |
| Не начат           | дата начала в будущем                                                                         |
| В срок             | остальные случаи                                                                              |

«Сегодня» считается в часовом поясе проекта.

## 9. Доска управляющей команды

Отдельная страница «Доска продуктов», пункт меню виден только тем, у кого есть доступ. Даты и статус меняются и в проектах, и на доске; есть отдельная колонка с комментарием к статусу. **[Решено]**

**Правка на доске.** Править могут все участники управляющей команды. **[Решено]** Даты меняются в таблице, в панели и перетаскиванием краёв полосы; статус, ручной процент и комментарий в таблице и панели, статус ещё и перетаскиванием в канбане. Список статусов берётся из проекта продукта. Изменение попадает в историю продукта, ответственный получает уведомление. Если данные успели измениться, сервер отклоняет правку и просит обновить их. **[Предлагаю]**

**Таймлайн (по умолчанию).** Строки: команды и их продукты, команды сворачиваются. Полоса от начала до конца, цвет по индикатору срока, заливка по прогрессу, линия «сегодня». Масштаб: неделя, месяц, квартал. На строке команды сводка: всего, в работе, под риском, просрочено. Дробление на портфели и проекты очень сжатое и не мешает: в фокусе команда и её продукты. **[Решено]** Команда выделена строкой; портфель и проект по умолчанию не занимают отдельных строк и показаны мелкой подписью у продукта; группировку по ним можно включить. **[Предлагаю]**

**Таблица.** Команда, портфель, проект, продукт, тип, ответственный, даты, статус, комментарий к статусу, прогресс, индикатор. Сортировка по столбцам.

**Канбан.** Столбцы по группам статусов, строки по командам, карточки перетаскиваются между столбцами. **[Решено]** Правила перетаскивания **[Предлагаю]**:

- если в группе одно состояние проекта, оно ставится сразу; если несколько, доска предлагает выбрать;
- если в проекте нет состояний этой группы, столбец не принимает карточку;
- перенос между строками команд невозможен, карточки без права правки не перетаскиваются;
- при ошибке сохранения карточка возвращается на место.

**Фильтры:** команда, портфель, проект, тип продукта, статус, индикатор, ответственный, «Показать закрытые проекты» (по умолчанию выключен), период (пересечение с датами продукта). Хранятся в адресе страницы, ссылкой можно поделиться с теми, у кого есть доступ. По умолчанию завершённые и отменённые старше 90 дней скрыты (считая с даты перехода в этот статус). **[Решено]**

**Карточка.** Клик открывает панель: описание, поля для правки, прогресс, список задач и встреч, переход в проект, если он доступен.

**Попадание на доску** автоматическое: все продукты неархивных проектов обычных команд. Продукты «Без портфеля» не показываются. Продукты закрытых проектов по умолчанию скрыты и не входят в сводки. **[Решено]** При включённом фильтре показываются название, даты, статус и прогресс, без описания и списка задач **[Решено]**; править их с доски могут только те, у кого есть доступ на правку проекта. **[Решено]** Админ пространства видит их целиком. **[Решено]**

Выгрузка в XLSX и PDF, история переносов сроков: вне первой версии.

## 10. Навигация

- В боковом меню: «Команды» с деревом «команда → портфель → проект». Сначала мои команды, ниже остальные.
- Проекты без портфеля отдельной группой.
- В чужом проекте метка «Только чтение».
- Адреса: `/:workspaceSlug/teams/:teamId`, `/:workspaceSlug/portfolios/:portfolioId`, `/:workspaceSlug/product-board`. Адреса существующих проектов и задач не меняются.
- Тексты на русском и английском; остальные 20 локалей получают те же ключи, этого требует проверка `check:sync`.

### 11.2. Модель данных

- `Team`: добавить `kind` (regular/management), `archived_at`; ограничение «одна управляющая».
- `TeamMember` (новая): team, member, role (admin/member); уникальность пары.
- `Portfolio` (новая): workspace, team, name, description, logo_props, lead, sort_order, archived_at.
- `Project.portfolio`: FK, null для старых проектов, SET_NULL. PROTECT не подходит: мягкое удаление Plane обрабатывает его как каскад и удалило бы проекты. Удалить непустой портфель не даёт API.
- `ProjectMember.is_team_managed` и `manual_role`: признак доступа от команды и ручная роль, которая возвращается после ухода из команды. Действует старшая из двух ролей.
- `IssueType.kind`: meeting/product, null у остальных типов. Системный тип создаётся при первом обращении. `is_epic` у продукта не ставится: интерфейс открывает эпики по адресам, которых на сервере нет. `Issue.type = null` или тип без `kind` означает задачу, массового обновления старых записей нет.
- `ProductType` (новая): workspace, name, logo_props, color, sort_order, is_active, requirements_html.
- `ProductDetail` (новая, 1:1 с Issue): product_type, owner, manual_progress (0–100 или null), status_comment с автором и датой, closed_at. Даты берутся из `start_date` и `target_date`.
- `MeetingDetail` (новая, 1:1 с Issue): start_at, end_at, organizer, location, outcome_html; `MeetingParticipant`: meeting, member.

`closed_at` нужен для правила 90 дней: `Issue.completed_at` заполняется только для завершённых, у отменённых он пуст. `closed_at` ставится при переходе в «Завершено» или «Отменено» и очищается при возврате.

Обязательность полей и правила вложенности проверяются в сериализаторах обоих API: внутреннего (`plane/app`) и публичного (`plane/api`). У `Issue.parent` каскадное удаление, поэтому удаление продукта сначала обнуляет `parent` у детей в той же транзакции. Показ подзадач не скрывает записи, у которых родитель — продукт.

### 11.3. Права

Самая рискованная часть. Сейчас доступ проверяется по `ProjectMember` в `app/permissions` и примерно в 35 файлах с фильтром `project_projectmember__member`.

- **Запись:** команда даёт настоящие строки `ProjectMember` (`is_team_managed`): админ команды = Admin, участник = Member в открытых проектах. Существующие проверки записи не меняются.
- **Чтение:** единый помощник `readable_projects(user, workspace)` = явные проекты + открытые проекты всех команд для не-гостей пространства. Проверки GET и фильтры списков, поиска, аналитики, страниц, файлов и live-редактора переводятся на него.
- Фиктивное участие Guest для чтения **не используем**: такие люди попадут в списки участников и исполнителей и получат лишние действия.
- **Админ пространства:** сейчас ему тоже нужна запись в проекте, чтобы работать с его содержимым. Помощник чтения и проверки записи дают ему доступ ко всем проектам, включая закрытые, без такой записи.
- **Правка с доски:** управляющие не получают `ProjectMember`. Отдельный метод доски принимает только даты, состояние, ручной процент и комментарий, проверяет, что состояние из проекта продукта, и использует ту же запись истории и вебхуки, что и обычная правка.
- Доступ, выданный командой, нельзя отозвать в проекте: сначала меняется состав команды. При уходе из пространства, деактивации или понижении до гостя человек выходит из всех команд; при возвращении его добавляют заново.
- Нельзя оставить без админа ни команду, ни проект: такое действие отклоняется.
- Синхронизация `ProjectMember` выполняется при изменении состава команды, портфеля проекта и закрытости, в одной транзакции.
- Live-сервер обязан открывать документы читателям без права записи.

### 11.4. API (внутренний)

- `GET/POST workspaces/<slug>/teams/`, `GET/PATCH/DELETE .../teams/<id>/`, `.../teams/<id>/members/`, `.../archive/`
- `GET/POST .../teams/<id>/portfolios/`, `GET/PATCH/DELETE .../portfolios/<id>/`
- `POST .../projects/<id>/move/` с режимом предпросмотра изменений доступа
- `GET/POST/PATCH/DELETE .../product-types/`
- `GET .../products/` с отбором по команде, портфелю или проекту: продукты доступных читателю проектов с прогрессом и индикатором
- Продукты и встречи: существующие адреса issues, поле `kind` и вложенные `product` / `meeting`; фильтр `kind`
- `PATCH .../product-board/<product_id>/`: только `start_date`, `target_date`, `state_id`, `manual_progress`, `status_comment`; лишнее поле даёт 400
- `GET .../product-board/`: отдельный сериализатор, прогресс и индикатор считаются одним агрегирующим запросом, пагинация

### 11.5. Побочные места

Автоархивация и автозакрытие (`bgtasks/issue_automation_task.py`) не трогают продукты и предстоящие встречи. Продукты по умолчанию исключены из циклов, модулей, оценок и их графиков. Проверить импорт, экспорт, вебхуки, черновики, версии задач, публичные доски (`apps/space`), аналитику, дублирование, действия с несколькими записями.

## 12. Миграция и выкладка

- Слияние в `main` сразу обновляет продакшен, стенда нет; миграции считаем необратимыми. Перед каждым этапом нужна резервная копия БД.
- Все миграции добавляющие: новые таблицы и поля с null или значением по умолчанию.
- Флаг на пространство скрывает новую структуру до готовности.
- **Расширение чтения включается отдельно**, после проверки админом, какие проекты должны стать закрытыми. Открытые (Public) проекты, закреплённые за командами, станут доступны для чтения всем сотрудникам.
- Порядок: админ создаёт команды и портфели, раскладывает проекты, отмечает закрытые, назначает админов, включает флаг.

## 13. Этапы и приёмка

Каждый этап: отдельная ветка `feature/<name>` и отдельный PR.

| Этап | Содержание                                          | Критерий приёмки                                                                                                                                                                          |
| ---- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Команды, портфели, навигация, синхронизация доступа | Админ команды А управляет только своей командой; вход и выход из команды меняют доступ, ручной доступ сохраняется                                                                         |
| 2    | Чтение чужих команд, закрытые проекты               | Читатель видит открытый проект и получает 403 на любую запись (правка на доске проверяется в этапе 5); закрытый не находится нигде                                                        |
| 3    | Типы записей, продукты, справочник                  | Продукт без дат или типа не создаётся; удаление продукта сохраняет задачи; старые задачи работают как раньше                                                                              |
| 4    | Встречи                                             | Встреча видна в календаре с временем в поясе читателя; участники получают уведомления                                                                                                     |
| 5    | Доска управляющей команды: просмотр и правка        | Продукты всех команд на месте, прогресс и индикаторы верны; правка видна в проекте и истории; другие поля изменить нельзя; закрытые скрыты по умолчанию; остальным доступ закрыт и по API |

Этапы 1 и 2 можно делать параллельно с 3 и 4; этап 5 требует 1 и 3.

**Нефункциональные требования [Предлагаю]:** доска на 500 продуктов открывается до 2 секунд; число запросов к БД не растёт с числом продуктов; изменения ролей, портфелей и переносов пишутся в журнал.

**Проверка:**

- pytest на каждую строку матрицы 4.2 для обоих API, плюс утечки закрытых проектов через поиск, счётчики, файлы и прямые ссылки.
- Тесты формул раздела 8 на граничных датах, пустых продуктах и с ручным процентом (включая 0 и очистку).
- Тесты правки с доски: каждое разрешённое поле, чужое состояние, закрытый проект без доступа (403), перетаскивание в группу с одним, несколькими и без состояний.
- Прогон миграций на копии продакшен-базы.
- Ручной сценарий под пятью учётными записями: админ пространства, админ команды, участник, чужой, управляющий.
- `pnpm turbo run check:lint check:types`, `uv run ruff check .`, `check:sync`.

**Вне первой версии:** внешние календари, повторяющиеся встречи, продукты из нескольких проектов, свои типы и поля, зависимости продуктов, экспорт доски, мобильное приложение.
