# Operations Dashboard layout v2 — review

**Review date:** 2026-09-28  
**Verdict:** Accept the panel hierarchy as a visual direction, with the contract and order changes below before implementation. This is a design review of the current checkout, not a claim that the proposed interactions already work.

## Alignment with the baseline

- The 12-column desktop grid, six current-snapshot KPIs, no greeting hero, paired Workload/Attention, paired Timeline/Deadlines, and full-width Projects breakdown follow baseline §§5–6. The deep tabs follow §7's separate destinations and scope preservation.
- Use the baseline's 3/5/4 distribution for Progress/Delivery/Project status **unless the actual content proves 4/4/4 more legible**. V2's 4/4/4 is within the grid system, but gives the two-series chart less width than the baseline; do a 1440px and 1280px visual check with long labels.
- Badge each panel and mixed-time column: **Hiện tại** for KPI, Progress, Top projects, Workload, Attention, Deadlines; **Trong kỳ** for Delivery and cycle intersection. In Projects, label `Completed now` and `Completed in period` separately. A selected historical period must not make current snapshots look historical. Timeline's today marker is a current marker inside a period view.
- Preserve baseline §5 responsive rules, theme tokens, keyboard equivalent for charts, and table-local horizontal scrolling. The v2 ASCII only defines desktop.
- The “one screen” claim needs a more honest target. At 1440×900, the six 88–104px KPIs, a 210–240px chart row, a 260–320px Workload/Attention row, headers, gaps, and padding leave the Timeline/Deadlines and Projects table below the fold. Call the first three rows the 30-second viewport and the rest one-scroll supporting detail; test at 100% and 200% zoom.

## UX risks and recommended edits

1. **Truthful scope and time.** Put the temporal badge in panel headers and in mixed-time table headings. Keep global Period control, but say “7 ngày tới · Hiện tại” on deadlines because that window is anchored to today, not the selected chart period. Provide the resolved scope/time in tooltips and empty states.
2. **Clickable affordances.** Remove “click drill” arrows from the mock until selection descriptors, matching counts, route targets, and focus return work. The current KPI drawer is a useful pattern; Project/Workload cells require their own validated selections.
3. **Dense table fit.** V2's Projects table can exceed a 1280px content area. Use sticky Project identity, a local horizontal scroll, sensible minimum column widths, and a visible period label. Do not shrink text below baseline §5 sizes or put the whole page in horizontal scroll.
4. **Preview completeness.** Make “5 of N”, “10 of N”, and View all labels explicit. The Workload and Attention lists must not imply that their rows add to a workspace distinct total. Keep Unassigned visually separate and show inactive assignments without labeling them unassigned.
5. **Responsive and failure states.** Specify 1024–1279, tablet, and mobile layouts; per-section loading/error/unavailable states; long names; 0-issue projects; unscheduled cycles; and selected historical periods. Allow panel height to grow at zoom/i18n.
6. **Terminology.** WIP warning means `started > threshold`, not capacity or productivity. “At risk” needs a declared predicate (for example overdue OR blocked), and “running cycle” needs an exact status/date definition. Keep these controls hidden until the server validates them.

| 4. Workload deep tab    | **M** | Search/sort controls, readable WIP warning, Unassigned/inactive handling, and validated member-cell drilldown. Project matrix/last activity is a separate contract extension.                                                            |
| 5. Timeline deep tab    | **M** | Two-pane bar/axis view, today marker, unscheduled group, independent pagers, then zoom. Verify 7-day deadline window independent of Period and large-cycle performance.                                                                  |

Keep Insights as the existing embed for this pass; scope-inheritance strip and presets depend on a tested config handoff and can follow the three deep views. Defer the optional Project summary drawer, CSV (until export scope/backend is specified), advanced project matrix, last activity, `No update`, and any drag editing. Continue excluding burndown, builder, leaderboard, and AI summary. These cuts preserve the baseline's core count/list and ACL guarantees without representing missing backend fields as ready UI.
