### Changed

### Fixed

- **api (MCP)** — Alias de routes v1 pour aligner nos endpoints sur le SDK MCP officiel (`plane_sdk`), qui a fait évoluer ses segments : `work-items/{id}/pages/` (module work-item-pages, servi jusqu'ici sous `issues/`) et `work-item-properties` / `work-item-properties/{id}/options/` / `work-items/{id}/work-item-properties/{id}/values/` (module work-item-properties, servi sous `properties/`). Ajout additif (mêmes vues, anciennes routes conservées) → les outils MCP `list/attach/detach_work_item_page` et `*_work_item_property*` résolvent désormais. Zéro migration ; 8 tests de résolution.
- **web/work-item-types** — Correction d'un crash `DeepMap should be used with functions with a consistent length` (page Runtime Error) au rendu du détail d'un work item dans un projet à work item types activés. `getProjectIssueTypes` (`core/store/issue-type.store.ts`) est un `computedFn` mémoïsé par une `DeepMap` qui exige une arité d'appel constante ; 3 appels internes passaient 1 argument alors que les autres en passent 2 → selon l'ordre de rendu, l'un plantait. Les 3 appels internes passent désormais `activeOnly=false` explicite (arité 2 partout ; comportement inchangé).
- **api (sécurité, revue adversariale)** — Les endpoints d'activité **per-user** `GET /api/workspaces/:slug/user-activity/:user_id/` et **export CSV** `POST .../export/` appliquent désormais la règle `guest_view_all_features` (helper `workspace_activity_visibility_q`, introduit par le module `workspace-activity-log`). Auparavant un guest projet (`guest_view_all_features=False`) consultant l'activité d'un autre membre voyait l'activité de **tous** les work items du projet (titres, changements) via `issue_detail`, pas seulement ceux qu'il a créés — sur le feed JSON (guest workspace) comme sur l'export CSV (membre workspace mais guest projet). Corrigé sur les 2 endpoints ; 3 tests ajoutés ; non-régression admin/member validée (E2E API vivante). Leak identique aux findings BK-1/WB-1 du module `workspace-activity-log` (nouveaux endpoints déjà corrigés).
- **web** — Les entrées du menu déroulant « plus » de la sidebar workspace (Views, Analytics, Archives) **naviguent** désormais correctement : au clic, le volet flottant se **ferme** (`toggleExtendedSidebar(false)`) au lieu de rester ouvert par-dessus la page (il appelait `(true)`), ce qui donnait l'impression que le bouton ne faisait rien.
- **web/work-item-page-embed** — La carte cliquable insérée par la commande `/page` affiche désormais le **titre courant** de la page (lu depuis le store, `observer` + fetch dédup), au lieu du `data-name` figé à la création (« Untitled ») qui restait périmé après un renommage. Aligné sur le comportement du widget « Link pages ».
- **web/space (i18n, dev+build)** — Les apps Vite consomment `@plane/i18n` depuis la **source** (alias) : le `dist` publié du paquet n'embarque pas ses fichiers de langue, donc l'import dynamique `../locales/*.json` ne se résolvait pas et l'UI affichait les **clés i18n brutes** (labels non traduits). Vite gère nativement le glob dynamique des locales depuis la source.
- **api/workspace-pages (sécurité, revue adversariale)** — Le PATCH d'une page workspace rejette `is_locked`/`archived_at` : un membre ne peut plus verrouiller ou archiver la page **publique** d'un autre utilisateur en contournant les endpoints dédiés `lock/`/`archive/` (réservés à l'auteur ou à un admin). Basculer une page wiki en privée purge les visites récentes des autres utilisateurs (leur titre/logo/owner ne fuit plus dans `/recent-visits`).
- **web/workspace-pages (revue adversariale)** — Les getters de `WorkspacePageStore` sont scopés au workspace courant (plus de fuite de pages entre workspaces dans le cache accumulé) ; l'empty state du wiki utilise les clés i18n réellement définies (`workspace_empty_state.wiki.*`) au lieu d'afficher la clé brute.
- **api/views-publish (sécurité, critique)** — Les vues publiées appliquent désormais leurs `rich_filters` côté serveur (endpoints publics `space`). Auparavant le filtrage reposait sur le champ legacy `query`, jamais renseigné par l'UI actuelle : une vue filtrée publiée exposait tout le backlog du projet à un visiteur anonyme (liste + détail). Le filtre échoue désormais fermé (queryset vide) si un filtre stocké est inapplicable.
- **api/views-publish** — La suppression d'une vue dépublie son `DeployBoard` (l'anchor public ne reste plus actif après suppression). UI : l'action « Publish »/badge « Live » n'est proposée qu'aux admins (l'API réserve publish/unpublish à l'ADMIN projet).
- **api/pages-nested (sécurité)** — La validation du parent applique le filtre d'accès (`owned_by` ou public) et exclut les pages archivées : impossible de rattacher une sous-page sous la page privée d'un autre utilisateur, ni de l'utiliser comme oracle d'existence. Remontée d'ancêtres protégée contre les boucles infinies (set de visités) et re-parentage concurrent sérialisé (verrou `select_for_update` ordonné) pour empêcher la création de cycles.
- **web/pages-nested** — Une sous-page archivée individuellement reste atteignable dans l'onglet Archived et ne s'affiche plus sous un parent actif.
- **web/pages-nested** — L'action « New sub-page » est aussi disponible depuis la barre d'outils d'une page ouverte (`editor/toolbar/options-dropdown.tsx`), et plus seulement depuis le menu des lignes de la liste des pages.
- **api/intake-email (sécurité/robustesse)** — Webhook idempotent via `message_id` (dédup `external_id`), scope de throttle dédié (`intake_email`), et émission de l'activité + notification + version de description à la création (parité avec l'intake in-app). Correction du libellé i18n de la pastille de provenance.
- **web/views-publish (a11y)** — Le badge « Live » d'une vue publiée est rendu comme `<button>` (au lieu d'un `<div>` cliquable) : accessible au clavier et désactivé pour les non-admins.
- **api/work-item-time-tracking (intégrité, revue adversariale)** — Identité externe (`external_source`/`external_id`) rendue **create-only** (ignorée en PATCH sur les deux surfaces), dédup 409 ajoutée au create interne (parité avec la v1), et contrainte d'unicité partielle en BDD `(project, external_source, external_id) WHERE deleted_at IS NULL` (migration `0126`) — l'idempotence d'import résiste désormais aux races. Décisions documentées en spec : lectures non gatées par le toggle (soft-gate produit), listes non bornées (contrat SDK).
- **web/work-item-time-tracking (revue adversariale)** — L'édition d'un worklog peut désormais **vider la description** (le champ est toujours envoyé en édition) ; types `TIssueWorklog.logged_by`/`logged_by_detail` alignés sur le backend (`null` si l'auteur a été supprimé — FK `SET_NULL`).
- **api/epics (intégrité/cohérence, revue adversariale)** — Convertir en epic un work item déjà rattaché à un cycle/module est refusé (le guard « pas d'epic en cycle/module » ne couvrait que l'ajout du lien) ; les listes cycle/module excluent les epics en défense en profondeur ; la recherche (`search-issues`) exclut les epics des pickers cycle/module/sous-item (jamais du picker parent) ; l'API interne expose `is_epic` en lecture (le web route un epic ouvert en pleine page vers le bon store) ; l'`estimate_point` est strippé des mutations d'epic.
- **web/epics (revue adversariale)** — Correction d'une régression : la modale d'édition de work item épingle le store standard (elle n'édite jamais d'epic) et ne se bloque plus sur un fetch en échec ; un clic sur un enfant depuis le peek d'un epic ouvre bien son peek (second `IssuePeekOverview` projet) ; le panneau propriétés du peek d'un epic masque estimate/cycle/module/parent (rejetés côté serveur) ; le bouton Subscribe du peek d'un epic cible le bon service ; la navigation directe vers `/epics` sur un projet sans work item types redirige vers les work items ; le tooltip du compteur d'epics est internationalisé (19 locales).
