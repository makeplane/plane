## Findings

### F1 — Backend filter works correctly

All 4 buckets resolve correctly against `target_date` relative to today. Combined with `not`, `and`, `__in`, and `__exact` operators. The user-reported "filter not working" on `/profile/.../assigned|created|subscribed/` is **not a backend defect** — earlier live network capture also confirmed correct server-side filtering. Defect (if any) lives in frontend serialization or rendering.

### F2 — Unknown bucket values silently no-op (graceful fallback)

`IssueFilterSet._progress_tracking_q(values)` returns empty `Q()` when no value matches a known bucket (`off_track`/`due_today`/`at_risk`/`on_track`). Empty `Q()` is a no-op in `.filter()` — queryset is **not** restricted. Consistent with priority/state filters but surprising for callers expecting strict validation. **No fix recommended** (matches pattern across filters); test documents the behavior.

Location: `apps/api/plane/utils/filters/filterset.py:292-316`

### F3 — Null `target_date` issues excluded from all buckets

Issues with `target_date=NULL` correctly never match any bucket (SQL comparisons against NULL yield UNKNOWN, filtered out). `not__in` also excludes them — by design.

### F4 — Test harness gotcha: `BaseModel.save()` overrides `created_by`

`Issue.objects.create(..., created_by=user)` does **not** persist `created_by` in tests because `BaseModel.save()` (`apps/api/plane/db/models/base.py:23`) consumes `created_by_id` from `save()` kwargs only, then defaults to crum `get_current_user()` which is `None` in test context. Workaround for tests:

```python
issue = Issue(..., created_by=user)
issue.save(disable_auto_set_user=True)
```

This is a test-infrastructure consideration, not a production bug — request-driven flows set crum's current user correctly.
